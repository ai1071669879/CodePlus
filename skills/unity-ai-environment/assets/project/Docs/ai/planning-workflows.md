# Unity 策划与版本协作

<!-- ai-rule: planning -->

策划可以直接描述目标、已知 ID/名称、场景和验收预期，无需提供内部路径、节点 GUID 或固定技术模板。AI 先定位真实文档/数据/工具，核对身份与职责，再把需求转成可追溯预览。自然语言关键词是工作意图，不代表已经安装命令解析器或编辑器插件。

## 版本需求、拆分与修订

读取实际版本文档及来源修订，保留关键原文指针。按阶段、状态、入口、成功/失败/中断、重复进入、奖励/消耗、依赖、兼容和验收检查歧义与冲突；事实、建议、待确认问题分开。

任务按完整业务职责及已有可复用机制拆分，说明依赖、可并行范围、文件冲突和可观察验收；不按章节机械建文件或把每条规则做成一个任务。未确认内容标注风险，继续不依赖它的工作。

需要跨人/跨会话追踪时使用 Tasks/index.json + 任务 Markdown，按 configuration.md 的 source、approvals、acceptance 记录来源、修订、实际负责人和证据；已有任务轻量修改直接回填。策划、人类实现者和最终验收负责人按实际团队分工登记，AI 不替本人认领或验收。待确认修订只给风险提示，不阻止候选拆分。

文档变化先给旧/新要求及受影响任务预览；按用户同步指令更新建议，保留原状态、认领人和人工记录。已完成任务受影响时提出具体重验条件，不自动清空历史或改回未开始。

## 配置：定位、预览、修改、正式导出

1. 确认本工程哪些是配置源、哪些是客户端/服务端导出或生成代码；如果源在独立工程，先取得本机路径并另核规则、账号授权、已有改动和正式工具。不能从导出目录反推不存在的源表。
2. 从业务描述、ID或名字定向找表/行/字段及真实使用方，检查关联键、取值范围、单位、默认/缺失语义和受影响功能。无法确认字段含义时标待核对，不凭名称推断。
3. 生成行级旧/新差异，注明源文件、行键、关联数据、客户端/服务端/生成 C# 影响与验收场景；只读预览不冒充已保存。
4. 只有源工程已授权且正式编辑/校验/导出入口可用时实施。保留格式和公式/关联；用正式工具生成同批产物。工具未接入时交付可执行预览和缺项，不直接修补导出 JSON、二进制或生成 C#。
5. 检查源、同批跨端产物和生成代码的一致性、关联 ID、非预期重导出差异；按改动做编译与正常/失败/边界业务验证，记录版本、命令和结果。正式导出成功不等于玩法验收完成。

配置格式、文件扩展名、导出命令、ID规则和目录全部由目标项目登记。没有配置源写入能力时仍可完成导出侧定位及预览，不宣称具有统一 Excel/JSON 自动写入能力。

## 事件图、流程图与内容编辑

先确认目标图、触发入口、节点真实语义、参数、连线和客户端/服务端执行位置；复用已经验证的节点组合，检查必填值、配置/资源引用、变量作用域、重复触发和清理时机。

用业务语言给出当前行为、拟修改后结果、旧/新参数、影响范围和风险。编辑前再核目标/旧值，避免把预览应用到已变化的图。编辑器若支持受控预览/应用接口，只在其明确能力范围内使用；没有接口就由有权人员在现有编辑器操作。

保存后运行项目真实结构校验/导出工具，核对源图和跨端产物差异，再验证成功/失败/默认分支、异常退出、重复触发及奖励/消耗。结构校验不能证明业务语义；分支、随机、多出口和循环需单独检查。

节点能力不足时记录所需行为、输入输出、相近图和具体缺口，由程序实施节点/执行器扩展；策划继续负责图内容及整体流程验收。不得拼出不等价图掩盖缺能力，不能手改序列化文本或生成产物绕过编辑器维护。

## 资源与跨职责交接

策划需求涉及 UI/美术/程序时保留同一目标与验收上下文，按真实文件和责任交接，不要求提需求者先猜技术归属。场景、出生点、Prefab等内容使用项目已登记的编辑工具；内容权限不能扩大为编辑器实现权限。

交付分别标明分析/预览、源已保存、正式导出、编译、运行/联调和负责人验收状态，给出对应证据。发现跨职责变化时具体说明文件、所需负责人和不受阻碍的工作，不丢失整体验收目标。
