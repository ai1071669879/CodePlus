# 任务正文模板

任务元数据仅在 Tasks/index.json 登记，字段、状态与校验统一见 configuration.md；这里不维护第二份状态表。正文记录需求和证据，来源/修订放 source，审批放 approvals，负责人验收放 acceptance。候选可未认领，完成必须有真实负责人及验收依据。

## 目标与来源

记录原始需求、来源/修订及可观察的期望行为，区分已确认事实和待核对问题。

## 契约与判据

重构、重建、替换既有设计或跨模块职责调整的任务必须附 `Tasks/<id>-contract.md`（模板见 task-contract.md），本节写明契约路径与优先级声明；普通任务写「不适用」及理由。判据尽量可机械判定：契约检查退出码、定向测试、产物基准（见 golden/README.md）、原始命令输出。

## 范围与复用

记录允许文件、职责、现有接口及其路径、调用方和约束；共享机制或职责变化须有负责人确认记录。方案以**结构差异表**登记，不以整段方案文字登记：新增/删除/改名项、为什么不能复用现有 X、归属模块、每行验收方式。

## 验收

记录正常行为、关键边界、受影响旧流程、真实门禁命令及必要的运行/性能/兼容性证据。分步门禁与被延后的收口门禁分别记录；延后项在关闭前保持未验证，任务不得报完成。

## 进展与证据

按实际工作追加变更文件、执行命令、退出码、决定性输出和结果；保留已有记录。多要点指令的每轮报告附编号回执（完成/未做/阻塞，一行一项），完成状态由本人负责人确认。

## 未验证项与阻碍

每项写明缺少证据、原因、影响与处置：补证据、重新分派、负责人接受风险或本次范围外。
