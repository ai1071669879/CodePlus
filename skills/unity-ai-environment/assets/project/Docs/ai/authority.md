# 文档权威登记

<!-- 模板：项目初始化后由维护者填入真实文档；未填之前本表不构成对任何文件的授权宣告。 -->

项目里同时存在行为规格、实现参考、历史任务记录与已退役代码。它们对实现的约束力不同，但文件本身不带等级标记，AI 与人都容易把「历史描述」当作「现行要求」复刻。本表是唯一登记处：实现前按本表判定引用对象的权威等级，与代码冲突时按等级处理，不按文件新旧猜测。

## 等级

| 等级 | 含义 | 冲突时 |
| --- | --- | --- |
| **权威** | 现行行为规格；实现必须满足 | 代码与权威文档不一致时，先核实并列出差异，不静默选边 |
| **参考** | 设计意图、示例与历史说明；可用于理解，不作验收依据 | 只作定位线索，结论回到代码、测试与已记录裁决 |
| **已失效** | 曾被实现过、现已废止的约定 | 只可读作历史；不得据此实现或据此否决现行设计 |
| **记录** | 任务过程与既往裁决 | 引用时必须回填到当前任务证据，不继承旧结论 |

## 登记

初始化后按下表登记本项目真实文档；每行写明等级、最后确认日期与范围限制。

| 文档 | 等级 | 最后确认 | 说明 |
| --- | --- | --- | --- |
| [project-rules.md](project-rules.md) | 权威 | <YYYY-MM-DD> | 任务行为规则正文 |
| [configuration.md](configuration.md) | 权威 | <YYYY-MM-DD> | 配置字段与管理命令的唯一说明 |
| [task-contract.md](task-contract.md) | 权威 | <YYYY-MM-DD> | 契约模板与判定口径 |
| `<行为规格文档>` | 权威 | <YYYY-MM-DD> | <覆盖范围；条款级复核见下> |
| `<实现参考/框架说明>` | 参考 | <YYYY-MM-DD> | <以现行实现为准的范围> |
| `<已退役实现目录>/` | 已失效 | <YYYY-MM-DD> | <退役日期；仅作对照；新代码禁止引用> |

初始化器生成的 `project-adaptation.md` 与 `project-baseline.json` 属**记录**：前者是初始化时的盘点结论，后者是静态快照，都不声称语义或运行验证；源码漂移后须重新取证。

## 待复核条款

与现行实现不一致或从未在现行代码上确认的条款登记在这里。**复核完成前不得作为实现依据，也不得据此否决新设计。**

| 条款 | 现象 | 处置 |
| --- | --- | --- |
| `<文档 §条款>` | <与代码的差异事实> | 复核后二选一：判定为已失效并登记日期，或修正实现使其符合规格 |
| 测试规模基线 | 历史计数属快照，可能随用例增删失效 | 以当轮实际运行的原始输出为准 |

## 维护

- **重构收口时更新**：任务结束时，凡本轮改变了某文档条款的语义，立即在本表登记失效日期与替代者；不留给下一轮。
- **失效条款必须写日期与替代者**：只写「已过时」而无替代者的条目无效，等同未登记。
- **契约引用本表**：任务契约的 `[Superseded]` 块引用本表条目，不自行发明失效声明。
- **不做第二份状态表**：文档等级只在本表维护；任务状态仍只登记在 `Tasks/index.json`。

## 判定示例

- 实现读取行为规格文档的语法：权威，必须满足。
- 实现参照已退役目录的类结构：已失效，只可借鉴，不得复制命名与职责划分。
- 引用历史任务里「已完成」的结论：记录，必须在本轮重新取证。
