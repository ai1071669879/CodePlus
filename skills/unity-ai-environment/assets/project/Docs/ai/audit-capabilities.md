# Unity 专项审计能力与证据

本页定义何时使用、需要什么输入、应交付什么证据；实现由 project-profile.capabilities 登记。初始六类能力均未接入；本包没有通用捕获解析器，也不会安装编辑器脚本或改动工程。初始化时核对现有工具/技能，再登记 skill、入口、命令、输入格式、版本和限制；仅找到实现时标 located，实际验证后才标 verified。

| 能力 id | 触发与输入 | 输出及结论边界 |
| --- | --- | --- |
| gc-audit | 反复分配/GC卡顿；限定源码、Profiler分配数据、场景与构建上下文 | 候选位置、每次字节/调用量、每帧频率、热身/池扩容阶段、对象规模与Player包含性；静态模式不能直接证明持续运行分配 |
| cpu-audit | 脚本热点/批量单位/列表刷新；限定模块或调用链、Profiler证据 | 帧耗时、调用数、规模复杂度、实际执行条件、候选优先级和改前改后证据；扫描器命中不是瓶颈结论 |
| memory-snapshot | 高内存或泄漏怀疑；真实Memory Profiler快照、捕获环境和必要对照 | 总量、分类、引用根、持有链和归属；区分Editor/Player，原始托管堆字节不能替代对象遍历后的类型归因 |
| profiler-frames | 长帧/瞬时卡顿；多帧捕获、Editor/Player、设备/构建与场景 | 慢帧分布、耗时采样、调用次数、GC/分配证据与背景操作；长帧不自动等于GC，附近资源路径不等于根因 |
| shader-build-log | 变体/编译/包体异常；实际构建日志或Editor日志及平台/管线/构建上下文 | 阶段计数、保留/剥离/编译变体、耗时和序列化程序体积；理论关键字组合不能证明最终保留数量或优化收益 |
| unused-classes | 删除/清理类型前；目标程序集、当前编译产物、序列化资源及反射/注册根 | 直接与递归不可达候选、入口证据、排除范围和待人工确认项；无文本引用不等于可删除，动态引用和外部资源仍可能存在 |

## 接入和使用

先核对目标项目的 Unity 版本、包/捕获格式与当前真实接口，选择已安装且适配的工具。无法读取某格式时保留原文件并说明需要的工具；不随意修改、伪造解析结果或把历史项目的特殊排除签名套到当前捕获。

源码候选需要结合程序集引用、编译宏、平台限制、注册路径和生命周期；调用链存在不证明会运行。跨平台或热更路径要确认实际构建包含性；不可达类的序列化引用、反射、事件订阅/发布以及运行时资源装载单独核验。编译产物不新鲜或缺资源包时标明范围未知，不直接删除。

性能对比记录工具版本、场景、对象规模、设备/构建、预热状态、采样窗口和指标。区分一次性加载/池扩容、持续帧负担、Editor污染和Player执行。默认不做大范围插桩；需要改工程或导出捕获时按授权和现有工具实施。

Shader 改动后需要同条件后续构建日志；内存问题按实际需要用相同场景前后/多次快照核对持有增长；GC/CPU结论需要实际运行样本。编译、静态扫描和单张截图不替代这些仪器。

## 报告

提供输入文件及上下文、工具/命令与退出码、具体文件/类型/采样项、已证事实、候选及置信限制、影响/验证条件和未覆盖范围。高优先级性能结论必须有对应运行证据；无法复现时保持候选，不把建议写成已确认根因或收益。已确认的修复仍需改后复测并回填任务证据。
