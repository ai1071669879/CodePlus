# Unity 项目 AI 通用规则

<!-- ai-rule: engineering -->

本页补充 project-rules.md，按本次修改的实际影响读取。工程根、版本、平台、包、框架和工具以 profile 与当前工程证据为准，不预设固定目录、API、渲染管线或热更方案。

## 职责与权限

| 职责 | 可承担的工作 | 边界 |
| --- | --- | --- |
| 程序 | 已授权玩法、UI、业务数据及编辑器代码 | 共享机制、协议/存储、依赖与发布按敏感职责处理 |
| 框架/性能维护 | 已登记的基础机制、资源/网络/性能维护 | 不因角色名自动得到包、插件、工程设置或治理权限 |
| 策划 | 版本需求、配置源、事件图内容、正式导出与业务验收 | 不手改生成 C#、节点类型实现或框架代码 |
| 美术 | 已授权资源、材质、场景、Prefab | 不据资源目录权限修改程序、配置或事件业务数据 |
| TA | 已授权 Shader/渲染资源和明确限定的代码 | 同时满足职责、资源与代码范围，不能用资源范围扩大 C# 权限 |
| 维护者 | 用户/路径登记与团队治理 | 仍遵守当前任务、工具与平台执行权限 |

角色只是模板，可与现有岗位映射；所有初始路径为空。按文件实际职责登记普通路径、类型限制、file_grants、code_paths和owned_paths；字段说明统一在 configuration.md。检查器执行这些已配置约束，不能证明岗位语义、正式生成来源或编辑器操作正确，仍须交付证据。

## 生命周期、异步与线程

注册/注销、进入/退出、资源取得/释放和异步取消必须与所属对象实际生命周期配对。复用既有基类和模式，不因 Unity 回调名字相同就忽略项目初始化顺序。

对象销毁、窗口关闭、场景切换、重复进入和重连后，旧任务不能向新状态回写。处理重复订阅、取消、异常观察和所有权；访问 Unity 对象/主线程 API 前确认线程约束，后台计算与对象访问分离。

验收覆盖本次相关的首次进入、退出重入、取消/销毁/场景切换，记录是否残留订阅或异步回写。编译通过不能证明生命周期正确。

## 资源、序列化、Prefab 与 UI

使用项目现有资源加载、引用管理和释放接口，明确持有者、释放时机及重新进入行为；不要另造与现有资源管线并行的体系。

资源新增/删除/移动与 .meta 配套，保留 GUID；核对序列化字段兼容、Inspector 数据、嵌套 Prefab、覆盖项、场景引用及导入结果。不通过重建 GUID 隐藏引用丢失。场景/Prefab/大型二进制资源并行编辑前明确归属。

UI 初版先确认实际 Prefab、控件、现有业务接口和绑定生成方式。若使用生成绑定，先由正式工具导出，AI 只改手写逻辑；如果工程没有绑定生成器，沿用当前实现，不额外引入。

修改 Prefab 前清楚提示目标文件、拟改节点/组件/序列化字段、必要性、引用或表现影响及最小验证。任务与路径已授权时提示后实施，不因 Prefab 另设审批；多人编辑冲突先协调。额外文件授权可用 file_grants 限定 `.prefab` 与 `.prefab.meta`，不因此开放场景或其他资源。

验证真实控件展示、交互、重复点击、数据未就绪、关闭后回调与资源清理；生成绑定不一致时指出缺控件/需导出项，不猜字段。未经过人工最终复核时，交付明确标记“UI逻辑初版，待人工复核”，不能据初版交付把任务标为最终验收完成。

## 性能与日志

高频回调、批量对象、列表刷新和资源加载改动先确认频率、规模和基线，检查分配、重复查找、字符串构造、创建销毁及日志。复用已有缓存/池/批处理，同时定义失效和清理。

不把 LINQ、闭包、async 等语法一律列为错误；优化依据实际频率、Profiler 和可维护性。记录场景、对象数量、设备、构建、帧耗时/GC/内存等指标，前后条件可比；Editor 数据用于定位，Player/目标设备用于相应结论。采样相关性不等于根因。

使用项目真实 Logger 及分类约定；未定位统一入口前先核实，不硬套特定类名或新增业务日志体系。日志包含诊断必要字段，控制频率和构造开销，不输出凭据、个人数据或完整线上负载。

专项审计按 [审计能力与证据](audit-capabilities.md) 选择输入、工具和可接受结论；未接入的分析器不伪称可调用。

## 程序集、依赖、热更与平台

读取实际程序集引用、平台约束、编译宏和 Editor/Runtime 边界；涉及 AOT、IL2CPP、裁剪、热更或包更新时检查当前工程采用的方案。程序集、包清单/锁文件和 ProjectSettings 默认列为敏感路径。是否允许 AI 修改由目标项目现有制度决定；迁移时保留原有明确禁令及专门确认，不以新增敏感授权取代更严格规则。

只有当前任务明确涉及、本人具有普通及敏感授权、负责人与项目流程允许时，才用工程正式方式修改；否则交付影响、缺失引用、替代限制与交接信息。不得以修复编译为由自行增加引用、装包或调整发布设置。

影响 Player/资源包/热更包时，检查目标平台、旧版本兼容、发布顺序及回退。纯局部任务不无条件构建所有平台，Editor 编译不能证明 Player、裁剪或热更加载正确。

## 网络、存档和跨端数据

业务使用既有请求接口与修改底层通信机制分开判断。遵守服务端权威，检查失败、超时、重复响应、断线重连与幂等；客户端展示不自行决定结算。

明确配置缺失、旧数据、字段演进、默认值及存档兼容，不以静默默认值掩盖错误。跨端导出、协议/存档格式按敏感职责与版本发布流程执行；使用脱敏测试样本验证读取和回退。

## 验收顺序

先检查受影响程序集无新增编译错误，再做相关 Editor/运行/回归；按改动补资源导入、Player/设备、性能、服务端及兼容验证。各层分别记录命令、版本、环境和结果，未做的明确标记。相同检查无新证据不重复，连续失败三次停止该项循环并保留排查信息。
