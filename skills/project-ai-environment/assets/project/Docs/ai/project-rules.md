# 通用项目 AI 协作规则

## 任务入口与四项原则

<!-- ai-rule: principles -->

先理解，再编码；简单优先；精准修改；以验收驱动执行。

任务开始读取本规则、project-profile.json、access-policy.json 和命中的 context-index 条目。查询当前身份，记录目标、允许路径、验收方式、当前分支/HEAD 与已有改动。资料不全时先做可完成的只读定位，不要求用户预判最终会改哪个层次。

默认在当前分支工作；新建/切换分支、提交、推送、外部发布遵守用户指令和项目流程。不得覆盖或撤销他人的已有改动。无 Git 时说明不适用，不自行初始化版本库。

## 契约与权威

<!-- ai-rule: intent -->

任务附 `Tasks/<task>-contract.md`（模板见 [task-contract.md](task-contract.md)）时，**契约在其点名的 `[Keep]`/`[Rewrite]`/`[Forbidden]`/`[Superseded]` 范围内优先于本文件与旧规格的通用条款**。被列入 `[Rewrite]` 的路径，现状代码只是证据，不是权威；「现有代码如此」「沿用现有合同」不能作为设计依据。契约未规定而影响实现的冲突先报告阻塞，不自行裁决。**契约不超越提交授权、凭据处理与验证等级**：高风险改动仍按 `verification` 要求独立验证，`[Rewrite]` 只决定允许改什么，不决定要验证多少。

不附契约时按本文件执行：先查找、复用既有实现，最小兼容改动。**重构、重建、替换既有设计、跨模块职责调整必须附契约**，否则不得开始实施。

引用任何文档前先按 [authority.md](authority.md) 判定等级：权威条款必须满足；参考与记录只作定位线索；已失效条款不得据此实现，也不得据此否决新设计。发现文档与实现不一致时列出具体条款与影响，不静默选边。

禁止项与允许新增的 public 类型必须落在契约机器块中；实施收口前运行 `python tools/ai/contract_check.py check --contract Tasks/<task>-contract.md`，退出码 0 才进入工程门禁。契约检查不替代构建、测试与独立验证；产物基准见 [golden/README.md](golden/README.md)。

## 身份、岗位与路径

<!-- ai-rule: identity -->

access-policy.json 是写入范围的登记来源；账号未登记、角色未知或范围不确定时只读。自述岗位、本机缓存和 git user.name 是定位线索，不是远端认证或新增授权。

<!-- ai-rule: scope -->

只修改当前任务必要且本人已授权的文件。路径、文件类型、内容归属和附加授权按 access-policy.json 及 configuration.md 执行；deny 优先。不能改用他人账号、修改检查器或扩大目录来完成当前任务。自述岗位与登记不符时暂停该部分写入，不沿用旧缓存代替核实。

权限表由获授权维护者管理。业务跨模块影响须显著说明；需要新增职责或共享契约时由负责人确认，但已有任务内已经明确授权的正常实现不重复索取许可。路径允许不代表发布、认证、协议或存储兼容性已经确认。

凭据通过平台受控通道使用，不写入共享模板、日志或任务文件；不把个人目录、令牌、内网地址和线上个人数据复制到新项目。

## 理解、复用与实现

先在目标模块查找入口、调用者、数据流、相近实现和现有工具，使用当前源码/测试/已跟踪决定确认事实。先限定目录搜索，有证据再扩大；导航不能证明代码仍被执行。

在设计前明确核心概念、实际可复用类型/签名、文件责任与验收边界。按领域职责组织实现，不把文档章节或每条规则机械映射为新文件。优先最小兼容改动，不为暂定需求新增抽象或无关重构。

修改前区分业务、共享机制、外部接口和生成物。保持现有初始化时机、异常处理、并发、资源所有权、数据兼容和可观察性约定。日志用项目现有入口，避免高频噪声与敏感数据。

<!-- ai-rule: generated -->

生成文件必须从已确认的源和正式工具更新；工具不可用时说明缺少的入口并给出可核查预览，不手改产物制造“通过”。生成物登记只有 project-profile.json 一处权威来源。依赖、构建、存储/协议和发布改动按敏感职责及兼容性验证执行。

## 阅读与交付深度

<!-- ai-rule: grading -->

轻量任务读取目标及必要调用方，直接检查本次行为，简述改动和结果；标准任务补相关模块、复用机制与关键失败/边界/旧流程；专项任务补共享机制、数据/平台兼容、性能或发布证据及回退。

这三档控制阅读、实施和交付深度，不是新增审批、不改变账号权限或台账要求。按实际影响判断，不按文件数或代码量；一行关键状态修改也可能是专项。发现影响扩大时升级验证，已明确范围不重复询问。只读定位/预检只交付发现与依据，不要求编译或建档。下列风险表决定证据强度，两者分开使用。

## 风险与验收

<!-- ai-rule: verification -->

| 风险 | 情形 | 所需证据 |
| --- | --- | --- |
| 低 | 文本、注释、无逻辑调整 | diff 与引用自查 |
| 中 | 有现有测试/构建覆盖的局部实现 | 对应工程门禁与定向回归 |
| 高 | 跨模块、生命周期、并发、安全、不易被现有门禁捕获的性能/不变量 | 独立复核/重跑及相关专项验证 |
| 关键 | 发布、持久化或外部契约 | 高风险证据加兼容、回退与发布验证 |

门禁以项目登记的真实命令、原始退出码和决定性输出为证据。没有可执行门禁就写未验证；静态扫描、编译、运行、性能和发布分别报告。修复引入的编译错误后再进行依赖编译的运行检查。

按调用者、共享状态和兼容边界选择必要的正常/失败/重复/回归场景。测试验证行为，不仅复述实现；不降低或修改既有测试标准来让改动变绿。无新改动或证据不重复运行相同检查；同一检查持续失败三次后停止循环，保留错误和阻碍。

## 执行节奏与回执

<!-- ai-rule: execution -->

**方案以结构差异表提交，不以长文提交**：新增/删除/改名的类型或文件、为什么不能复用现有 X、归属模块、每行验收方式。表即范围；交付里出现表外文件属 shape drift，退回。超过一屏说明该步过大，先拆分。

**分步门禁**：每个改动可执行代码的实施步骤结束编译被改工程并跑定向测试，不把门禁整体推到末尾；纯文档/元数据步骤改为校验链接或结构。延后是记录下来的决定：契约 `[Gate]` 写 `deferred until <收口门禁>` 且机器块 `deferred_gate` 置 `true`，该门禁以未验状态保持打开，任务不得报完成。放弃编译必须写明替代的捕获方式，并把替代物当作门禁。

**多要点回执**：一条指令含两项以上要求时，进度与完成报告先给编号回执（`1 完成 <证据>` / `2 未做 <原因>` / `3 阻塞 <缺什么>`），一行一项、按用户顺序；无证据的项写未做；总结不得超出回执。

## 协作

需求解释、设计与跨切面一致性由任务负责人承担，最终验收也由负责人给出。只有职责与接口已明确、能完整写成任务简报且可独立推进的工作才外派；一处小改或串行关键路径直接处理。没有协作者或工具不支持时，不假设其存在。

任务简报包含目标、精确范围、复用点/接口、上下文、已定设计、验收、验证命令和停止条件。执行者不自行扩大设计，缺信息时报告阻碍。高风险独立验证前后记录源/测试/配置摘要，验证者不得改源码；构建产物单独排除。

报告保留结论、改动文件、复用点、证据（路径/行号/命令/退出码/输出）、假设与阻碍；观察是决策输入，不自动成为新任务。每个未验证项须获得证据、重新指派、明确接受风险或划出范围，不能留空后宣布完成。

## 追踪和修订

<!-- ai-rule: tracking -->

多人接力、版本级或跨会话工作使用 Tasks/index.json 与对应 Markdown；独立当次小修复可不建档。已有任务回填原文件，保留负责人、状态、人工记录和来源修订。人主动认领并最终验收，AI 不替他人确认完成。

任务拆分围绕完整职责、依赖、可并行范围与验收条件；文档变化先展示影响，再按同步指令更新建议。未确认内容保留待核对标记，不阻止不依赖它的工作。

## 提交说明

<!-- ai-rule: commit -->

提交前读取目标工程已有提交约定，并在 conventions.commit_language 记录需要的语言；约定不明时遵守用户当前明确指令。标题说明改动行为和模块范围，关联变化再补原因、兼容/回退及真实验证，避免只有“更新”等空泛表述。核对最终暂存内容，范围变化后同步说明；生成说明不代表获得提交、推送或发布授权。

## 交付与声明

交付改了什么、为什么、影响范围、参考实现、执行过的检查及未覆盖风险。事实提供文件/行号或命令输出；推断单独标注。源码调用链、文档描述、采样相关性均不能单独证明实际可达、兼容或性能因果。

环境检查只检验规则和数据结构；audit 不是强制隔离，客户端钩子不是服务端授权。平台实际加载、CI 真实执行、工程运行和发布状态各自保留证据。

涉及工具接入、外部结果或质量门禁时，按 [工具接入规则](tool-integrations.md) 和 [质量证据流程](quality-workflows.md) 定向加载。启用模块不自动证明能力已验证。
