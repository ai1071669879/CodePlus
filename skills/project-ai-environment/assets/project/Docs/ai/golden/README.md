# 产物基准（golden）

<!-- 基准文件本身是判定物，不是文档；改动基准必须单独审阅。 -->

「像不像我预想的那样」无法直接判定，但**产物的稳定片段**可以：一段生成代码、一段序列化数据、一份导出清单。基准文件把这些片段固定下来，使任务契约可以用「与基准逐行一致」代替「人看一眼」。

## 适用对象

项目用正式工具生成的产物：代码、数据、清单、诊断输出格式。**不适用**于手写业务代码——手写代码由测试与评审判定，基准会把重构锁死。

## 登记

在任务契约的 `golden` 数组登记，路径相对仓库根：

```json
"golden": [
  {"path": "<本轮产物路径>", "golden": "Docs/ai/golden/<基准>.example"},
  {"path": "<可选产物路径>", "golden": "Docs/ai/golden/<基准>.example", "optional": true}
]
```

- `path`：本轮产物路径，由任务实际生成或修改。
- `golden`：基准文件，放在本目录。
- `optional`：`true` 时产物缺失只记 warning；默认缺失即违规。
- 基准文件命名用 `<目标名>.example`，避免与真实产物混淆、避免被构建工具误编译。

## 比较规则

[contract_check.py](../../../tools/ai/contract_check.py) 逐行比较，忽略：行尾空白、换行风格（CRLF/LF）、末尾空行。**不忽略**：缩进、空行位置、标识符、注释文本。基准与产物任一缺失（非 optional）即违规。

## 更新纪律

- 产物变化**先**改基准**再**提交实现，或与实现同一改动集；不允许「实现改完顺手更新基准」而不说明。
- 更新基准时在任务正文写明：哪一段为什么变、验收依据是什么、受影响的其它产物。
- 基准不得由实现者单方面扩大范围：多出的文件属于 shape drift。

## 首批建议

初始化后尚未登记基准。首个重构任务收口时，为主力产物各挑一个最小稳定样例（每个不超过 120 行），优先覆盖：

| 产物类别 | 目的 |
| --- | --- |
| 生成的一个典型类型/结构 | 锁住字段、键、特性、命名 |
| 生成的集合/容器类型 | 锁住索引、查询接口、构造方式 |
| 一次导出的顶层结构 | 锁住引用与时间/键的表示 |
| 一次生成物清单 | 锁住路径、命名与文件划分 |

选用真实产物中**已确认正确**的片段作为基准，不用手工构造的示例。
